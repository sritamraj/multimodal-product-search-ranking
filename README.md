# Large-Scale Multimodal Product Search & Ranking

A **multimodal product search** system: given a text query such as `black running shoes`, retrieve and rank products using product text + product images.

> **Important:** This repository intentionally does **not** contain invented benchmark numbers. Run the evaluation pipeline on a real catalog + relevance judgments and then copy the generated `results/metrics.csv` into the README.

## Architecture

```text
                    PRODUCT CATALOG
                         │
              ┌──────────┴──────────┐
              ↓                     ↓
          Product Text          Product Image
              ↓                     ↓
        CLIP Text Encoder       CLIP Vision Encoder
              ↓                     ↓
          Text Vector           Image Vector
              └──────────┬──────────┘
                         ↓
              Weighted Multimodal Vector
                         ↓
                     FAISS ANN
                         ↓
                  Top-N Candidates
                         ↓
                 Feature Ranker
                         ↓
                    Top-K Results
```

## Experiments

1. **BM25** — lexical retrieval baseline.
2. **Text-only embedding retrieval** — query vs product-text CLIP embeddings.
3. **Image-only retrieval** — query text vs product-image CLIP embeddings.
4. **Multimodal retrieval** — weighted fusion of product text + image embeddings.
5. **Multimodal + hard negatives** — train a lightweight pairwise reranker using difficult negatives from the retrieval stage.

The evaluation table is generated by `scripts/evaluate.py` and contains:

| Model                       |  Recall@10 |        MRR |    NDCG@10 |
| --------------------------- | ---------: | ---------: | ---------: |
| BM25                        | **1.0000** | **1.0000** | **0.9855** |
| Text Encoder                |     0.0417 |     0.1250 |     0.0548 |
| Image Encoder               |     0.2381 |     0.2167 |     0.2123 |
| Multimodal                  |     0.0774 |     0.3333 |     0.0921 |
| Multimodal + Hard Negatives |     0.0774 |     0.3333 |     0.0921 |

**These are the measured results from the supplied catalog and relevance judgments.**

Results are from a small catalogue. Larger-scale evaluation is planned.

## Dataset format

Put your catalog at `data/catalog.csv`:

```csv
product_id,title,description,image_path
p001,Black running shoe,Lightweight black road running shoe,data/images/p001.jpg
p002,White trail shoe,Trail running shoe with grip,data/images/p002.jpg
```

Put relevance judgments at `data/qrels.csv`:

```csv
query_id,query,product_id,relevance
q001,black running shoes,p001,3
q001,black running shoes,p002,0
```

Recommended real-world dataset options include Amazon product datasets, your own catalog, or another dataset for which you have the right to use the text/images. Do not commit copyrighted/private data unless you have permission.

## Setup

### 1. Create environment

```bash
python -m venv .venv
```

Windows:

```powershell
.venv\Scripts\activate
```

macOS/Linux:

```bash
source .venv/bin/activate
```

### 2. Install dependencies

```bash
pip install -r requirements.txt
```

### 3. Build embeddings + ANN index

```bash
python scripts/build_index.py --catalog data/catalog.csv --output artifacts/index
```

### 4. Evaluate all retrieval baselines

```bash
python scripts/evaluate.py \
  --catalog data/catalog.csv \
  --qrels data/qrels.csv \
  --index artifacts/index \
  --output results/metrics.csv
```

### 5. Train hard-negative reranker

```bash
python scripts/train.py \
  --catalog data/catalog.csv \
  --qrels data/qrels.csv \
  --index artifacts/index \
  --output artifacts/reranker.joblib
```

Then evaluate the reranker:

```bash
python scripts/evaluate.py \
  --catalog data/catalog.csv \
  --qrels data/qrels.csv \
  --index artifacts/index \
  --ranker artifacts/reranker.joblib \
  --output results/metrics.csv
```

## Hard-negative strategy

For each query, retrieve a candidate pool with the multimodal ANN system. Positives come from `qrels.csv`. Hard negatives are candidates that:

* are highly ranked by the retriever,
* are not labeled relevant for the query,
* and therefore look semantically similar but are wrong.

The reranker learns from pairwise positive-vs-negative feature differences.
